## 2. 项目概况

### 2.1 目标

把 R 包 `copykat` 的 CNV 推断流水线用 Python 重写，做到两点：

1. **数值等价性**：在相同 counts 矩阵、相同无监督 auto-baseline 模式下，pycopykat 与 R copykat 的 per-cell diploid/aneuploid 预测 + per-bin CNA 矩阵一致（ARI ≥ 0.9 为目标）。
2. **性能提升**：利用 NumPy/SciPy/Numba 向量化 + BLAS 并行 + 稀疏路径，把单患者墙钟从 R 原版 ~12 min/8核 降到 1 分钟以内。

### 2.2 不是什么

- **不是** R copykat 的 API-兼容 wrapper——公共 API 从零设计（`copykat(mat, config=...)` 返回 `CopykatResult`）。
- **不是** 有监督聚类器——不接受"已知正常细胞"列表作为默认工作模式（`norm_cell_names` 可选，验收测未用）。
- **不是** 与 3CA 论文 `cell_type` 标签（如 `Epithelial`/`T_cell`）做对比——3CA 本身是算法产出，不是金标准。本项目只验 **py 与 R 的一致性**。

## 3. 验收基准（Benchmark）方法

### 3.1 数据集

17 患者来自 5 个公开 scRNA-seq 研究：

| 癌种 | 数据 | 患者 | 细胞数区间 |
|---|---|---|---|
| Breast | Gao et al. 2021 | DCIS1, TNBC1-3 | 532 – 1480 |
| Lung | Kim et al. 2020 | P0019, P0034, P1028 | 2646 – 4434 |
| Colorectal | Lee et al. 2020 | SMC09, SMC16, SMC21 | 2048 – 2695 |
| Kidney | Obradovic et al. 2021 | Patient2/4/5 | 2704 – 4847 |
| Ovarian | Qian et al. 2020 | 11, 12, 13, 14 | 2600 – 6972 |

总 17 位患者，cell 数从 532 到 6972，跨度 >10×，覆盖小/中/大规模。

每位患者的原始 counts 矩阵由 `scripts/slice_dataset.py` 从论文总表中按 `sample` 列切出，`scripts/run_all_benchmarks.py` 统一驱动，生成：
- `<patient>/counts.tsv`（genes × cells 整数 counts）
- `<patient>/cells.csv`（cell 元数据，含 UMAP 坐标用于绘图，**不**用作对比 ground truth）
- `<patient>/r_out/`（R copykat 原生输出）

### 3.2 运行条件

- **硬件**：单机 8 核 CPU（性能 budget 对 py 和 R 完全一致）
- **R copykat**：默认参数，`n.cores=8`
- **pycopykat**：`CopykatConfig(n_jobs=8)`，无监督 AUTO baseline（即不提供 `norm_cell_names`）
- **两者输入**：同一 `counts.tsv`，同一 gene ID 类型（hg20 Symbol）

### 3.3 指标

| 指标 | 含义 | 适用范围 |
|---|---|---|
| **ARI** (Adjusted Rand Index) | 两个聚类划分的一致性，对标签置换不变 | 0.5 阈值区分"基本一致"vs"结构不同"；≥0.9 为近乎完全一致 |
| **Cohen κ** | 逐 cell 标签一致性（`diploid`/`aneuploid`/`not.defined`），对标签置换敏感 | κ < 0 + ARI ≥ 0.5 = "同一划分但 label 反转" |
| **FMI** (Fowlkes–Mallows Index) | 成对一致性的几何平均，比 ARI 更敏感但无校正 | 辅助验证 |
| **wall-clock (py_min, r_min)** | 每位患者端到端函数耗时，`scripts/compare_py_vs_r.py` 从各自 `*_runinfo.txt` 读取 | speedup = `r_min / py_min` |

指标计算在 `src/pycopykat/validation/metrics.py::compare_predictions`，对 `cell` 列做 inner join 后用 `sklearn.metrics` 计算（`adjusted_rand_score`、`cohen_kappa_score`、`fowlkes_mallows_score`）。

### 3.4 机制分类（truth-free）

用 py↔R 的 ARI 和 κ 把每位患者归入一个桶（`scripts/aggregate_py_vs_r_mechanism.py`）：

| mechanism | 规则 | 含义 |
|---|---|---|
| **matched** | ARI ≥ 0.9 且 κ ≥ 0.9 | 近乎完全一致 |
| **R_label_flipped** | ARI ≥ 0.5 且 κ < 0 | 同一划分，diploid/aneuploid 标签反转 |
| **partial** | 0.5 ≤ ARI < 0.9 | 中等一致，无干净 label flip |
| **different_clusters** | ARI < 0.5 | 结构性划分不同 |

该分类**不引入任何外部 truth**，仅从 py 和 R 的两份预测相互比较得出。

### 3.5 回归门禁

每次性能 patch 提交前：

1. `uv run pytest tests/unit -x` —— 全部通过（当前 125 个）
2. `uv run pytest tests/test_regression.py -m slow -x` —— Kim P0028 端到端 R-vs-py 通过
3. 目标患者（通常 Kim P0019 pilot）ARI vs R 漂移 ≤ 0.005
4. 17 患者 sweep mean ARI 漂移 ≤ 0.005，最差单患者漂移 ≤ 0.05
5. 墙钟不增加

验收期间**无一次回归门禁触发**。

## 4. 性能优化时间线

总 13 次性能 commit + 若干文档/scaffold/basement 提交。完整链条见 `git log --grep='perf\\|feat\\|bench'`。

### 4.1 Phase-1 — 算法替换 + NumPy 向量化（A1-A8，8 commits）

| Patch | Commit | 核心思路 | 贡献 |
|---|---|---|---|
| **A1** | `8a7109c` | MCMC 1000-sample 均值 → 解析 Poisson-Gamma 后验均值 `(α+Σy)/(β+n)` | 分段核 ≈20× |
| **A2** | `9a4b319` | `_segment_one_cell` Python 循环 → `np.add.reduceat` 单次 C-level 汇总 + 广播 | 分段核累计 ≈50× |
| **A3** | `19f865f` | 去掉 step 8 重复 Ward 聚类，复用 `baseline_norm_cl` 的 `labels`（需 stage-2 子集化 + 连续 id 重标） | 整体 1.1× |
| **A4** | `a006d6d` | `predict_ploidy` 返回 `Z`，`Z_final` 复用（两次 linkage 的输入和距离相同） | 整体 1.1× |
| **A5** | `3d9e7bd` | `ward_cluster_with_min_size` 回传 condensed 距离，silhouette 复用 | baseline 阶段 1.5-2× |
| **A6** | `504b9c5` | `filter_cells_by_chrom_coverage` 双循环 → per-chrom `np.add.reduceat` 向量化 | QC 阶段 2-10× |
| **A7** | `6a6544f` | `aggregate_to_bins` 全量 bool mask → per-chromosome `np.searchsorted` | bin 聚合阶段 1.2× |
| **A8** | `9c67213` | Kalman kernel 输入改 Fortran-order，去掉 `Y[:, j].copy()` | kernel 2.9× |

Phase-1 后 Kim P0019 由 ~90 s 降到 ~38 s。17 患者 sweep（`f85ebd5`）mean speedup 4.38× → 10.54×，mean ARI 0.878 → 0.922。

### 4.2 Phase-2 — 稀疏感知 + 算法试探（S1, S2, B1, 3 commits）

scipy-best-practices 原则驱动：counts 矩阵本身 ~88 % 稀疏（验证：Kim P0028 密度 12.1 %）。

| Patch | Commit | 核心思路 | 贡献 |
|---|---|---|---|
| **S1** | `975ac90` | counts 保持 CSR/CSC 穿过 QC 步骤 1-3；`getnnz(axis=...)` 替代 `(X>0).sum()`；per-chrom 统计用 `X.indices + np.bincount` | 步骤 1+3+7 3.4× |
| **S2** | `0793843` | VST `log(√x+√(x+1))` 在 x=0 处 = 0，保持零值 → 只对 `.data` 做 log(sqrt+sqrt)，centering 处 densify | VST 步骤 2.97× |
| **B1-scaffold** | `ea66972` | 解析 Gamma-KS（opt-in gated），microbench 测 MC vs analytic 速度差 | 决策：**不采纳**——analytic 反而慢 2.8×（`gamma.cdf` grid 代价 > MC RNG+sort），且断点集差 26 % |

S1 单独把单患者峰值 RSS 从 990 MB 降到 271 MB（−72.6 %），允许并行更多患者。S2 是纯数学安全的快速补充。

### 5.3 非 matched 案例的解读

- **R_label_flipped 的 3 位患者**：`aneuploid/diploid` 的语义本质是"哪个 Ward cluster 更像正常基线"。两个实现（R `mixtools::normalmixEM(arbvar=FALSE)` vs py `sklearn GaussianMixture(covariance_type='tied')`）在 F-test σ² ratio 边界时可能选不同 cluster 作 baseline，进而把 label 整体翻转。**py 没声称自己更对，R 也没错**——这是两个算法在等价度量下的边界分歧，下游分析可以用 κ<0 的信号触发人工复核。
- **Kim/P1028 (partial) 和 Lee/SMC16 (different_clusters)**：两者都是 **≥95 % 肿瘤细胞** 的退化 regime。copykat 算法要求有足够的 diploid 细胞作为基线参考，否则 baseline 选择不稳定。这是 **copykat 算法本身的限制**（Gao et al. 2021 原文已指出），不是 pycopykat 的实现缺陷——R copykat 在同一数据上同样不稳定（比较 py 和 R 本身都是两个在极限条件下挣扎的算法实例）。
- **其余 12 位 matched**：ARI 和 κ 均 ≥0.9，其中 6 位 ARI=1.0000，4 位 ARI≥0.99。pycopykat 的 CNV 推断在**正常条件下与 R 实现等价**。

## 8. 已知限制与取舍

1. **退化 regime 的 ≥95 % 肿瘤样本**：Kim/P1028（partial）和 Lee/SMC16（different_clusters）。这是 copykat 算法本身对"需要 diploid 参考"的硬性依赖，R 实现同样不稳定。建议下游：对 `warnings` 含 `unclassified.prediction` 的样本触发人工审核。
2. **`dynamicTreeCut` 简化版**：V1 port，覆盖 2-6 个 subclone 的常见情形；WGCNA 原版 `dynamicTreeCut` 的所有 cutoff 分支未完整移植。对当前 benchmark 无影响。大规模（≥20 k cells）场景若发现 subclone 差异再做 V2。
3. **R `ward.D` vs scipy `ward.D2`**：scipy 只实现 `ward.D2`，距离按欧氏平方累加；R copykat 用 `ward.D`（直接欧氏和）。数学上差一个单调变换，对 Ward 层次结构的 tie-breaking 可能产生最末 ulp 差异，实测未观察到 ARI 可量化下降。
4. **B1 gated 路径**：`config.breakpoint_ks="analytic"` 可选但默认 `"mc"`。基于 microbench 证据（2.8× 慢 + 26 % 断点差）放弃默认切换；保留 opt-in 方便未来在 `mc ≥ 10000` 极端场景试验。
